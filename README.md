# AJU PDV — 변경관리(Change Control) 시스템

AJP-OP-702 절차서의 4단계 양식(신청서 → 평가서 → 계획서 → 완료보고서)을 웹에서 작성하고,
단계마다 관리자가 승인/반려로 진행 여부를 결정하는 사내 웹 시스템입니다.

- 로그인 직후 첫 화면은 비워두고 "개발중" 문구만 표시. 좌측 사이드바의 **Change Control** 메뉴로 들어가야 실제 현황판이 보입니다.
- Change Control 현황판은 **요약 / 상세 현황 / 설계변경 관리대장** 3개 탭으로 구성
  - 요약: 승인 대기·진행 중·완료 건수, 단계(접수/평가/계획/승인)별 현황, 요청기한이 표로 정리된 현황 요약
  - 상세 현황: 진행 중인 건을 단계(접수/평가/계획)별로 나눠서 표시, 완료된 건은 별도 표. 문서 제목을 누르면 해당 문서로 이동
  - 설계변경 관리대장: 연도별로 묶인 엑셀 대장 형태 — 제품명/연도/완료여부로 검색·필터링, 열 클릭 정렬. 문서번호·접수일·평가·계획·완료일을 누르면 해당 문서/단계로 바로 이동. 비고는 관리자가 직접 입력/수정 가능, 단계는 접수/평가/계획/완료 4가지로 표시
- "+ 변경접수" 버튼 → 신청서 작성 페이지로 이동. 제품은 미리 등록된 목록에서 복수 선택하고, **요청 기한을 반드시 지정**해야 접수됩니다.
- 변경관리번호는 `CC-MD-YYMMDD-NNN` 형식으로 자동 채번 (같은 날짜 안에서 001, 002...로 증가, 날짜가 바뀌면 001부터 다시 시작)
- 신청서 → 평가서 → 계획서 → 완료보고서가 각각 별도 페이지(`/cc/[id]/application`, `/evaluation`, `/plan`, `/report`)로 분리되어 있고, 상단 단계 표시를 눌러 이동합니다. 각 단계는 관리자가 승인하거나 반려 사유와 함께 반려할 수 있습니다.
- 각 단계 폼에서 파일을 첨부할 수 있습니다 (여러 개 가능, 데이터베이스에 저장됨 — 별도 파일 저장소 설정 필요 없음).
- 평가서의 부서명은 자유 입력 대신 4개 부서(Quality Compliance Team / Product Development Verification Team / Production Management / Medical Business Team) 중 선택합니다.
- 반려된 항목은 **그 변경관리를 접수한 본인(또는 관리자)만** 수정해서 다시 제출할 수 있습니다.
- **가장 처음 가입하는 사람이 자동으로 관리자**가 됩니다 (그 이전엔 로그인 화면 대신 회원가입 화면이 뜸). 그 이후 가입하는 사람은 "승인 대기" 상태가 되고, 관리자가 `/admin/users`에서 권한(관리자/A/B/C)을 정해서 승인해야 로그인할 수 있습니다. (이 화면은 아직 사이드바 메뉴에 없고 주소로 직접 들어가야 합니다 — 별도 관리자 페이지로 정리할 예정)
- 관리자는 `/admin/users`에서 전체 회원 목록을 보고, 이미 승인된 회원의 권한도 언제든 바꿀 수 있습니다. (이메일 인증은 아직 없음 — 발송 방식을 정하면 추가 예정)

## 기술 구성 (참고용)

- **Next.js** (웹 화면 + 서버 로직을 한 번에 처리하는 프레임워크)
- **PostgreSQL** (데이터 저장소) — Vercel에서 클릭 몇 번으로 생성
- **NextAuth** (로그인/회원 관리)
- **Vercel** (호스팅 — GitHub 저장소를 연결하면 자동으로 배포됨)

첨부파일은 별도 저장소 없이 데이터베이스에 바로 저장됩니다 (설정할 것이 없어 간단하지만, 한 번에 올릴 수 있는 용량이 총 10MB로 제한되어 있습니다 — 아주 큰 파일을 많이 올리셔야 하면 말씀해주세요, 별도 저장소 방식으로 바꿀 수 있습니다).

서버, 데이터베이스에 대한 사전 지식이 없어도 아래 순서를 그대로 따라 하면 배포할 수 있습니다.

## 처음부터 배포까지 (A-Z 가이드)

### 1단계. Vercel 계정 만들고 이 저장소 연결하기

1. https://vercel.com 접속 → **Sign Up** → "Continue with GitHub" 선택해서 GitHub 계정으로 가입/로그인합니다.
   (이 프로젝트 코드가 이미 GitHub 저장소 `junguimin1998-coder/change-control`에 올라가 있으므로, 같은 GitHub 계정으로 로그인해야 이 저장소가 보입니다.)
2. Vercel 대시보드에서 **Add New... → Project** 클릭
3. 저장소 목록에서 `change-control`을 찾아 **Import** 클릭
4. Framework Preset은 자동으로 "Next.js"로 잡힙니다. 그대로 두고 아직 **Deploy 버튼을 누르지 마세요** (데이터베이스와 환경변수를 먼저 설정해야 합니다). 화면을 그대로 두거나 나중에 이어서 진행해도 됩니다.

### 2단계. 데이터베이스 만들기 (Vercel Postgres)

1. 방금 만든 프로젝트 화면에서 상단 **Storage** 탭 클릭
2. **Create Database** → **Postgres** 선택 (Neon 기반, 무료 제공량 있음)
3. 이름은 기본값 그대로 두고 **Create** 클릭
4. 생성 후 안내되는 대로 **Connect to Project**를 눌러 방금 만든 `change-control` 프로젝트에 연결합니다.
   - 이 과정에서 `POSTGRES_URL`, `POSTGRES_PRISMA_URL` 등의 환경변수가 프로젝트에 자동으로 추가됩니다.

### 3단계. 환경변수 설정하기

프로젝트 화면에서 **Settings → Environment Variables**로 이동해서 아래 값들을 추가합니다.
(`.env.example` 파일에도 동일한 설명이 있습니다.)

| 이름 | 값 | 설명 |
|---|---|---|
| `DATABASE_URL` | 2단계에서 생긴 `POSTGRES_PRISMA_URL` 값을 그대로 복사해서 붙여넣기 | 데이터베이스 접속 주소. Storage 탭 → 만든 DB 클릭 → `.env.local` 탭에서 값 확인 가능 |
| `NEXTAUTH_SECRET` | 임의의 긴 문자열 | 로그인 세션 암호화 키. 터미널이 있다면 `openssl rand -base64 32`로 생성, 없다면 아무 긴 무작위 문자열(20자 이상)이면 됩니다 |
| `NEXTAUTH_URL` | 배포 후 생기는 주소, 예: `https://change-control-xxxx.vercel.app` | 처음엔 임시로 아무 값이나 넣고, 1차 배포 후 실제 주소로 다시 수정해도 됩니다 |

값 입력 후 각 항목마다 **Save**를 눌러 저장합니다. (환경은 Production/Preview/Development 모두 체크된 상태로 두면 됩니다.)

### 4단계. 배포하기

1. 프로젝트 상단 **Deployments** 탭으로 이동해 **Redeploy** (또는 처음이라면 **Deploy**) 버튼 클릭
2. 빌드 로그가 올라가면서 자동으로 데이터베이스 테이블까지 생성됩니다 (`npm run build` 안에 `prisma db push`가 포함되어 있음)
3. 몇 분 뒤 "Ready" 상태가 되면, 화면에 표시된 주소(예: `https://change-control-xxxx.vercel.app`)로 접속해봅니다.
4. 만약 3단계에서 `NEXTAUTH_URL`에 임시 값을 넣었다면, 이제 실제 주소로 바꿔서 다시 **Save** 후 한 번 더 **Redeploy** 합니다.

여기까지 하면 사이트가 실제로 열립니다.

### 5단계. 관리자 계정 만들기

1. 배포된 주소로 접속하면, 아직 아무도 가입하지 않았기 때문에 **로그인 화면 대신 "최초 관리자 계정 만들기" 회원가입 화면**이 뜹니다.
2. 이름/이메일/비밀번호를 입력하고 가입하면 **이 계정이 자동으로 관리자가 됩니다.** 별도 환경변수 설정이 필요 없습니다.
3. 로그인하면 화면 상단에 "(관리자)"로 표시됩니다.
4. 실제 접수자(직원)들은 이후 같은 주소의 `/signup`에서 각자 회원가입하면 되는데, 이들은 **가입 즉시 로그인할 수 없고 "승인 대기" 상태**가 됩니다. 관리자가 `/admin/users`로 들어가서 권한(관리자 / A / B / C 중 하나)을 선택해 승인해야 그 사람이 로그인할 수 있습니다.

### 6단계. 이후 관리

- **직원 추가**: `/signup`에서 각자 가입 → 관리자가 `/admin/users`에서 권한을 선택하고 **승인** 버튼을 눌러줘야 그 직원이 로그인할 수 있습니다. (거절도 같은 화면에서 가능)
- **권한 변경**: 같은 `/admin/users` 화면의 "전체 사용자" 목록에서, 이미 승인된 회원의 권한(관리자/A/B/C)도 드롭다운으로 언제든 바꿀 수 있습니다. (단, 관리자가 한 명만 남은 경우 그 사람의 권한은 실수로 낮출 수 없도록 막아둠)
- **권한(A/B/C)의 의미**: 지금은 이름만 구분되어 있고 기능 차이는 아직 없습니다 (승인/반려는 "관리자"만 가능, 나머지는 모두 신청서 등 작성 가능). 나중에 역할별로 화면/기능을 다르게 하고 싶으시면 말씀해주세요.
- **코드 수정 후 재배포**: 이 저장소에 새 커밋을 올리면(main/이 브랜치에 push) Vercel이 자동으로 다시 빌드/배포합니다. 사람이 직접 서버에 접속해서 뭔가 할 필요가 없습니다.

## 화면 구성

- `/login`, `/signup` : 로그인 / 회원가입
- `/` : 로그인 직후 첫 화면 (현재는 빈 화면 + "개발중" 안내만 표시)
- 좌측 사이드바 → **Change Control** 클릭 시 이동:
  - `/change-control` : 요약 / 상세 현황 / 설계변경 관리대장 3개 탭, "+ 변경접수" 버튼
- `/cc/new` : 변경관리 신청서 작성 (AJP-OP-702-A14), 제품 복수 선택 + 요청 기한 지정 + 파일 첨부
- `/cc/[id]` : 개요 페이지 — 제목/제품/요청기한/전체 상태와 4단계 진행 표시, 각 단계 문서 목록(보기 링크)
- `/cc/[id]/application`, `/evaluation`, `/plan`, `/report` : 각 단계 문서(A14~A17) 페이지 — 내용 보기, 파일 첨부/다운로드, 관리자 승인/반려, 반려 시 접수자 본인의 재작성 폼
- `/admin/users` (관리자 전용, 사이드바에는 아직 없고 주소로 직접 접근) : 새로 가입한 사용자 승인/거절, 전체 사용자 목록/상태 확인

## 로컬에서 직접 실행해보고 싶다면 (선택 사항)

서버 지식이 없다면 이 부분은 건너뛰고 위 Vercel 배포만으로 충분합니다. 개발자가 로컬에서 확인하고 싶을 때만 참고하세요.

```bash
npm install
# .env.example을 복사해 .env로 만들고 값 채우기 (로컬 PostgreSQL 필요)
cp .env.example .env
npx prisma db push
npm run dev
```
